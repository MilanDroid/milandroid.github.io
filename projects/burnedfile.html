File sharing · Google Drive

Burnedfile

Self-destructing file sharing over the sender's own Google Drive. The file lands in their Drive and stays private there. Burnedfile mints a restricted link; when the link expires or its views run out, the file is hard-deleted from the sender's Drive.

What it honestly does

The product says this out loud, at the moment it matters, and so does this page.

Burnedfile controls distribution of the link, not the content. Once bytes reach a viewer, no restriction applies — screenshots, Save-As and re-uploads are unstoppable. What it actually promises is revocation of future access, plus an audit trail.

Country and IP restrictions are deterrent controls, not security boundaries. They stop casual and accidental access. They do not stop a VPN.

Files are removed within minutes of the final view or expiry, and always within 90 minutes. Not "instantly" — the architecture cannot keep that claim, so it does not make it.

Why this section exists. Most tools in this category overpromise. Writing the limits down first made the engineering decisions easier: every control below is built to be honest about what it can and cannot enforce.

How a view is decided

Every request for a shared file runs an ordered series of checks. The order is deliberate: a link that is dead is never refused for who the viewer is, which keeps the reasons in the audit trail honest.

Simplified. The decision depends on nothing on purpose: time, geography, password checks and every counter are handed in, which makes the whole restriction surface testable as a table of plain values.

Two lifecycles

A link and the stored file are tracked separately, because a link can die long before the bytes are gone — and the gap between those two moments is exactly what the cleanup closes.

Sealed is the moment the last view is spent: no new views, but the download that view already paid for may still finish. Burning to burned is the window the 90-minute promise covers.

A record that outlives the file

Every link the sender created stays listed with its state, its views and its expiry. A live link can be edited, given a new address, or revoked on the spot.

When the file is gone, the record stays: it is the sender's proof the deletion happened. And when a deletion fails, the list says so instead of pretending.

The audit trail shows when the link was created, each counted view, the finished download, the moment the link closed and the moment the file left the sender's Drive.

Link scanners and mail-security bots open links before people do. Those opens are listed apart and never counted as views.

Deterrents, labelled as deterrents

The form says it where the sender sets the rules: country and IP restrictions stop casual and accidental access, and do not stop someone using a VPN.

It also explains why: country is estimated from an IP address, and an IP allow-list means little behind the shared addresses most mobile networks use.

The narrowest permission Google offers

Burnedfile asks for one permission, the one Google grants per file. It can read and delete the files it uploaded, and cannot list, open or search anything else in the sender's Drive.

Revoking the connection in the Google account ends its access immediately.

Decisions worth explaining

The sender's own Drive

The file is stored in the sender's Google Drive, private, rather than in storage of Burnedfile's own, and is deleted from there when the link is done.

Two views by default

A security scanner at the recipient's company often opens the link first. The spare view stops that from using up the file.

Honest refusals

A dead link is refused as dead, never for who is asking. The audit trail records the true reason, so the sender can trust what it says.

The last view still downloads

Spending the final view seals the link instead of closing it, so the person who used that view still gets the file they were promised.

A notice that stays true

The recipient is told what will be recorded before opening the file, so that setting is fixed once the link exists. A setting that could change later would make the notice false.

Never their IP address

The sender is never shown a recipient's IP address, at any level of detail, including on export.
